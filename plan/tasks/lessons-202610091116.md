## 1. Renomear a pasta de um projeto Docker orfa os volumes sem avisar

**Padrão do erro:** fusão de `script/9router-federation/` + `script/9router-pool/` em
`script/9router/`. O nome do projeto do Compose é o nome do diretório quando não há `name:`
no arquivo. Em `docker compose up` a mudança de nome é silenciosa: o compose cria um
conjunto novo de volumes (`9router_...`) e deixa os antigos (`9router-federation_...`,
`9router-pool_...`) órfãos — com o DB de cada container dentro. Já existiam volumes órfãos
`9router_9router-001/002-data` de uma tentativa anterior, prova de que o cenário já aconteceu.

**Regra:** antes de mover/renomear qualquer diretório que tenha `docker compose`, fixar o
projeto com `name:` no topo de cada arquivo (e verificar com `docker compose config` que o
`name` resolvido é o antigo) **ou** passar `-p <nome-antigo>` em toda invocação. Conferir
também os prefixos de volume hardcoded no código (aqui: `9router-pool_` em `commands.py` e
`sync.py`) — eles só continuam corretos se o projeto não mudar.

**Correspondência:** `plan/reviews/review-202610091116.md` (verificação 7 e 8),
`plan/design/design-202610091116.md` (alternativas C e E).

## 2. `.gitignore` com `.env` exato não cobre `.env.<sufixo>`

**Padrão do erro:** ao separar o env em `.env.federal` / `.env.pool`, a regra `.env` do
`.gitignore` da raiz **não** casa com os nomes novos (ela é literal, sem curinga). O env
com o `JWT_SECRET` teria entrado no commit.

**Regra:** ao renomear arquivo de segredo para um nome com sufixo, atualizar o `.gitignore`
na mesma mudança e confirmar com `git check-ignore -v <arquivo>` (não só com `git status`).

**Correspondência:** `plan/reviews/review-202610091116.md` (verificação 13).
