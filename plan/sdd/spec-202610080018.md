## Contexto e objetivo

O 9Router expõe uma API compatível com OpenAI (`POST /v1/chat/completions`), mas o Claude Desktop
fala a API Anthropic (`POST /v1/messages`). Queremos um proxy "igual ao do Ollama"
(`internal/proxy/claude_desktop.go`) para o 9Router: um shell local que faz o mesmo trabalho de
segurança e disponibilidade que o Ollama faz, apoiado num conversor de protocolo já existente
(`SohaibKhaliq/9Router-Proxy`, clonado em `script/9router-claude/ref-9router/`).

Arquitetura híbrida escolhida pelo usuário:

```
Claude Desktop
   │  POST /v1/messages (Anthropic)
   ▼
[shell Go] 127.0.0.1:11435          ← port do claude_desktop.go
   │  /_gateway/health  → local
   │  POST /v1/messages/count_tokens → local (estimativa)
   │  /v1/models, /v1/messages → strip auth + readiness + reverse proxy
   ▼
[conversor Python] converter:8080     ← ref-9router (Anthropic ⇄ OpenAI)
   │
   ▼
[9Router] host:20338/v1/chat/completions (OpenAI)
```

## Requisitos

- **R1** — Shell Go escuta apenas em loopback (default `127.0.0.1:11435`, configurável por
  `GATEWAY_LISTEN_ADDR`) e recusa request cujo `Host` não seja loopback na porta do listener
  (mesma lógica de `allowsHost`, linhas 419–435 do original).
- **R2** — Shell Go recusa qualquer request com header `Origin` (bloqueia CORS no loopback,
  original linhas 306–311).
- **R3** — `GET /_gateway/health` responde `204` com header `X-9Router-Claude-Gateway: 1`
  (probe local, espelha `ProbeClaudeDesktop`, original linhas 172–196).
- **R4** — `GET /health` é repassado ao conversor (satisfaz o `test_proxy.py` e healthcheck do
  compose).
- **R5** — `POST /v1/messages/count_tokens` é respondido **localmente** por estimativa de tokens
  (heurística própria: ≈4 bytes/token sobre o texto da requisição), sem depender do conversor.
  Original: `anthropic.EstimateCountTokens`, linha 588.
- **R6** — `POST /v1/messages` e `GET /v1/models`: o shell **remove** `Authorization`, `Cookie` e
  `Proxy-Authorization` do cliente e faz reverse proxy para `CONVERTER_URL`
  (default `http://127.0.0.1:8080`), com `FlushInterval = -1` para SSE passar byte a byte
  (original linhas 126–130 e 365–368).
- **R7** — Se `GATEWAY_UPSTREAM_API_KEY` estiver setada, o shell injeta
  `Authorization: Bearer <key>` antes de encaminhar; caso contrário não envia credencial nenhuma.
  O valor vem do `.env` (ver R13); o cliente (Claude Code/Desktop) nunca precisa da key.
- **R8** — Readiness do upstream: antes de encaminhar, espera o conversor aceitar conexão TCP
  (poll 100 ms, timeout 10 s, cache 5 s) e responde `502` se não ficar pronto
  (original linhas 442–517).
- **R9** — Retry sem imagens: se o conversor responder `400` cujo erro mencione imagem/vision +
  "does not support|not support|unsupported", o shell reescreve blocos `image` por um aviso em
  texto (e o mesmo dentro de `tool_result`) e **refaz o request** (original linhas 636–950,
  sem o mapa `SupportsVision` — a resposta do upstream é a única autoridade).
- **R10** — O conversor Python entra no projeto como cópia de `ref-9router/app/{__init__,converter,main}.py`
  + `requirements.txt` + `Dockerfile`; aliases de modelo continuam só em `converter.py`
  (fonte única, sem duplicar no shell). **Ajuste de comportamento:** `MODEL_ALIAS_MAP` vira
  identidade (`claude-sonnet-5` → `claude-sonnet-5`, idem haiku/opus), porque o 9Router serve
  os próprios IDs Anthropic (ver Evidência), não `hc/*`.
- **R11 (amendado 2026-10-08, pedido do usuário: "não precisa do docker compose")** —
  **sem Docker**: `make up` sobe os dois processos locais lendo o `.env`
  (uvicorn do conversor em `127.0.0.1:8080` + binário do gateway em `127.0.0.1:11435`);
  `make down` mata; logs em `.run/`. Conversor alcança o 9Router em `127.0.0.1:20338`.
  O R11 original (compose com bind `127.0.0.1:11435:11435`) foi descartado junto com os
  Dockerfiles.
- **R12** — Go 1.27.1 instalado localmente em `~/.local/go` (aprovado pelo usuário nesta sessão);
  nada de sudo.
- **R13** — Configuração por `.env` no diretório do proxy (com `.env.example` versionado;
  `.env` no `.gitignore`). Variáveis:
  | Variável | Default | Quem usa |
  |---|---|---|
  | `GATEWAY_LISTEN_ADDR` | `127.0.0.1:11435` (`0.0.0.0:11435` no container) | shell |
  | `CONVERTER_URL` | `http://127.0.0.1:8080` (`http://converter:8080` no container) | shell |
  | `UPSTREAM_BASE_URL` | `http://127.0.0.1:20338/v1` | conversor |
  | `DEFAULT_MODEL` | `claude-sonnet-5` | conversor (modelo quando o cliente não envia `model`) |
  | `GATEWAY_UPSTREAM_API_KEY` | (obrigatória em runtime) | shell → injeta no upstream |

## Evidência (probe em 2026-10-08, 9Router em 127.0.0.1:20338)

- `GET /v1/models` + key → 200, lista `claude-sonnet-5` / `claude-opus-5` (IDs Anthropic).
- `POST /v1/messages` com `stream:true` → SSE **Anthropic** correto (`message_start`,
  `message_delta`, `message_stop`).
- `POST /v1/messages` **sem stream** → resposta em formato **OpenAI** (`object:chat.completion`,
  `choices`) — **quebrado**; é por isso que o conversor Python é necessário (R10).
- `POST /v1/messages/count_tokens` → `{"input_tokens":3}` OK.
- `POST /v1/chat/completions` → OpenAI OK.
- Ambos os clientes são suportados: Claude Code (`ANTHROPIC_BASE_URL=http://127.0.0.1:11435`)
  e Claude Desktop (gateway de terceiros na mesma URL). R1 limita aos dois à mesma máquina.

## Casos de borda-

- Conversor morre no meio do stream → o shell repassa o erro, sem deadlock.
- `CONVERTER_URL` inválido → falha clara na subida (`NewGateway` retorna erro, como o original).
- Porta 11435 ocupada pelo Ollama → erro de listen explícito; `GATEWAY_LISTEN_ADDR` para desviar.
- Body > 64 MiB → rejeitado (`maxRequestBodyBytes`).
- `count_tokens` com body inválido → erro Anthropic `invalid_request_error`, nunca pânico.
- Retry de imagem sem `messages` → no-op, resposta original repassada.

## Riscos e decisões em aberto-

- **Risco:** porta `11435` é a do gateway Claude Desktop do Ollama — colisão se ambos rodarem.
  Mitigação: `GATEWAY_LISTEN_ADDR` + mensagem de erro clara.
- **Risco:** heurística de contagem de tokens é aproximada; o Claude Desktop usa esse número para
  janela de contexto, não para cobrança. Aceitável — mesmo espírito do `EstimateCountTokens`.
- **Aberto:** a estimativa deve contar também `system` e `tools`, não só `messages`? (Decisão:
  sim, tudo que for string.)
- **Aberto:** credencial do 9Router — o compose atual não exige API key em `/v1`; `GATEWAY_UPSTREAM_API_KEY`
  fica opcional.
