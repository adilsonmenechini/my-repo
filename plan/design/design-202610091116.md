## Approach

Fusão das duas pastas em `script/9router/`, com um compose por stack e um Makefile único.
O nome do projeto Docker deixa de derivar do nome da pasta e passa a ser fixado por `name:`
no topo de cada compose — é isso que preserva os volumes vivos. O env é separado por stack
para que o gerador do pool (`create`/`scale`) não apague variáveis do federal. As ~9 chamadas
de `docker compose` no Python passam a usar uma constante única `COMPOSE_ARGS`.

## Components touched

- `script/9router/` (novo): recebe o conteúdo das duas pastas; `docker-compose.federal.yaml` (era `9router-federation/docker-compose.yaml`), `docker-compose.pool.yaml` (era `9router-pool/docker-compose.yaml`), `.env.federal`, `.env.pool`, `.env-example`, `.gitignore`, `Dockerfile` único, `Dockerfile.watch`.
- `script/9router/Makefile` (novo): substitui os dois Makefiles; alvos `federal-*` e `pool-*`.
- `src/server_pool/docker.py`: adiciona `COMPOSE_FILE`, `ENV_FILE`, `COMPOSE_ARGS`; template do compose ganha `name: 9router-pool` e `env_file: .env.pool`.
- `src/server_pool/commands.py`: 6 gravações de arquivo usam as constantes; ~6 invocações de `docker compose` ganham `*COMPOSE_ARGS`.
- `src/server_pool/sync.py`: 3 invocações de `docker compose` ganham `*COMPOSE_ARGS`.
- `tests/test_docker.py` (novo): cobre CA2/CA6.
- `README.md`: nomes de arquivo e de alvos Makefile atualizados + seção das duas stacks.

## Interfaces and data

- Nome do projeto Docker: `9router-federation` e `9router-pool` — **inalterado** (fixado por `name:` em vez do diretório). Volumes `9router-federation_*` / `9router-pool_*` e containers `sbx-*` idênticos.
- Rede `sbx-9router`: declarada nos dois arquivos, como hoje.
- Env: `.env` único → `.env.federal` + `.env.pool`. Interpolação via `--env-file`, container via `env_file:`.
- CLI do pool (`python3 pool.py ...`): inalterada.

## Alternatives considered

| Option | Pros | Cons | Chosen? |
|---|---|---|---|
| A: dois envs separados + `name:` fixo | sem interferência entre stacks; dados preservados; dono claro de cada env | exige `--env-file`/`-f` em todas as chamadas | yes |
| B: um `.env` compartilhado | menos flags | o `pool create/scale` regrava o `.env` e apagaria as portas do federal | no |
| C: renomear o projeto para `9router` (default do diretório) | nome "limpo" | abandona os volumes com dados e exige migração manual | no |
| D: pool mantém `docker-compose.yaml` default | zero mudança no Python | nomes assimétricos, contra o pedido R2 | no |
| E: redes separadas por stack | isolamento total | quebra a resolução por nome entre as stacks, que é o comportamento de hoje | no |

## Risks and edge cases

- Nome de projeto errado abandonando volumes → `name:` em cada arquivo + verificação ao vivo com `docker ps`/`docker volume ls` (CA6).
- Esquecer uma chamada de `docker compose` sem `-f` → constante única `COMPOSE_ARGS` + teste que falha se os arquivos não existirem.
- Commitar segredo ao renomear `.env` (o `.gitignore` da raiz só casa com o nome exato `.env`) → `.gitignore` local cobre `.env.federal`/`.env.pool` + verificação com `git status --ignored`.
- `make federal-down` destruindo o DB → `-v` movido para `federal-down-v` explícito.
- Testes do pool dependem do caminho `src/` → `tests/conftest.py` já trata; a pasta muda de nome, não a relativa.

## Result (fill in when done)

Construído como descrito. Desvios:

- `federal-down` ficou **sem** `-v` (o Makefile antigo da stack federal apagava os volumes
  sem pedir). O comportamento antigo passou a ser `federal-down-v` explícito. Mesma separação
  para o pool (`pool-down` / `pool-down-v`).
- Item novo, encontrado durante a implementação: o `pool-clean` antigo usava
  `docker volume ls --filter name=9router`, que casa também com os volumes da stack federal —
  `make pool-clean` apagaria os dados dela. O filtro virou `name=9router-pool_`.
- O compose do pool no disco estava editado à mão e divergente do template; foi regenerado a
  partir do template e a igualdade virou teste.
- O README do pool ganhou a seção "Duas stacks nesta pasta" no topo, além da atualização dos
  nomes de arquivo e de alvo.
